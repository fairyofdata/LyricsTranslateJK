# 수집 규격

가사를 모아 주시면 제가 `data/lyrics/<song_id>.json`으로 적재하고 분석합니다. **적재본은 `.gitignore` 대상**이고 저장소에는 해시와 추상 특징만 올라갑니다 (D6).

이 문서는 **붙여넣는 형식**만 정합니다. JSON은 제가 만듭니다.

---

## 1. 한 곡당 붙여넣을 것

```
### song: <원제> / <번안제>
### direction: ja2ko        (또는 ko2ja)
### source-artist: <원곡 가수>
### cover-artist: <번안 가수 또는 채널>
### cover-kind: fan         (fan / official / gold)
### cover-url: <있으면>

--- source
<원문 가사. 한 줄에 한 라인>
...

--- target
<번안 가사. 한 줄에 한 라인>
...
```

`###` 줄 중 모르는 것은 비워도 됩니다. **가사 두 덩이가 핵심**이고 나머지는 보조입니다.

## 2. 있으면 좋은 것 (없어도 됩니다)

| | 왜 필요한가 |
|---|---|
| **원문 독음** (가나 또는 한글 표기) | `phon` 계산의 검증용. 없으면 제가 생성하고 **그 생성이 틀릴 수 있습니다** |
| **섹션 라벨** (1절·후렴·브리지) | 정렬의 하드 경계. 없으면 제가 추정하고 어긋날 수 있습니다 |
| **재생 시간** 원곡/번안 | 번안이 절을 생략했는지 바로 드러납니다 (§4) |
| **댓글** — 특정 대응을 지목한 것 | **가장 값나가는 자료.** §3 참조 |

독음은 스트리밍 서비스 가사란에 같이 실려 있는 경우가 많고, 그러면 그대로 복사하시면 됩니다.

## 3. 댓글 — 좋아요 수가 아니라 지목 댓글

쓸 수 있는 것은 **「원어 어절 → 번안 어절」을 짚은 댓글**입니다. 그게 사람이 손으로 달아 준 "이 대응은 작동한다" 라벨이고, `phon` 모수와 `θ_mimic` 하한을 맞출 유일한 신호입니다 (D10·D34·D38).

좋아요 수와 "노래 잘한다"류는 **목소리·외모·편곡에 오염되어 쓸 수 없습니다.**

댓글란을 통째로 붙여 주셔도 됩니다 — 제가 지목 댓글만 골라냅니다. 다만 **작성자명과 본문은 적재본에만 두고, 저장소에는 어절 쌍과 그 IPA·자질 거리만** 남깁니다.

## 4. 곡 고르실 때 — 지금 부족한 쪽

| 필요 | 왜 | 현황 |
|---|---|---|
| **지목 댓글** | `phon` 모수와 `θ_mimic` 하한을 맞출 유일한 신호 | `s001` 채굴 완료 — 소리 쌍 7·keep 2 (2026-11-23). 다른 곡 0 |
| **ko2ja 방향** | 한→일을 먼저 완성한다 (D1) | **2곡** (`s011`·`s012`) |
| 공유 음독 漢字語가 적은 곡 | 과적합 가리기 (PLAN 2.6) | **충족.** `s002`~`s005` 넷 (D39) |
| 발음을 적극적으로 맞춘 번안 | 설계의 주 검증 대상 | **충족.** `s001` 모범 + `s005` 음차 상한 |

**"발음을 고려하지 않은 번안"도 버리지 마세요.** 대조군으로 필요합니다 — 평면의 `render` 쪽 끝이 어디인지, MT 앵커와 얼마나 가까운지를 그 곡들이 알려줍니다 (SPEC 8.8). `s002`·`s003`이 그 역할이고, **전면 개작**(`s004` 혜성)도 버리지 마세요 — 라인은 안 겹치는데 작품은 유지되는 사례가 `semantic_work` 축의 존재 근거입니다.

**독음은 가능하면 함께 주세요.** 지금까지 적재분에서 `s005`만 가나 독음이 제가 생성한 것이고, 그래서 그 곡의 모라 수는 **검증되지 않았습니다.** 다른 곡들은 사용자 제공 독음이 있어 대조가 됐습니다.

가장 값나가는 것은 **같은 곡의 커버 둘**입니다. 하나는 뜻 위주, 하나는 발음 위주면 가장 좋습니다 — 같은 선율·같은 원문에 두 전략이 찍히므로 다른 변수가 전부 통제됩니다.

## 5. 제가 하는 것

받으면 곡마다 이 순서로 돌립니다.

1. **적재** — `data/lyrics/<song_id>.json`. 라인 번호, 섹션, 분절 대응
2. **구조 점검** — 절 생략 여부, `1:0`·`2:1` 분절, 사용 가능 구간 확정
3. **행위 배분 분류** — 어절마다 `keep`/`sino`/`mimic`/`render` 중 실제로 무엇이 쓰였는지. **형태 유형 사전 분포가 맞히는지**가 RQ2의 자료
4. **공유 음독 漢字語 비율** — 분기점 A
5. **음절·모라 수 대조** — 슬롯 구간 포함률, 분기점 B
6. **지목 댓글 채굴** — 어절 쌍 라벨
7. **메타 기록** — `data/metadata.csv`에 해시와 집계값 (커밋 대상)

곡이 쌓이면 ③~⑤의 집계가 그대로 RQ2·분기점 A·B의 결과가 됩니다. **코드 없이 손으로 돌릴 수 있는 범위**이고, 그래서 M1 전에 결과가 나옵니다.

## 6. 저작권

- 가사 본문·독음·댓글 본문은 `data/lyrics/`에만 둡니다. `.gitignore` 대상입니다
- 저장소에 올라가는 것은 `data/metadata.csv`(해시·집계), 어절 쌍의 IPA·거리, 행위 배분 인덱스뿐입니다
- 공개 저장소이므로 커밋 전에 `data/`를 매번 확인합니다 (CLAUDE.md 규칙)
- 논문 인용은 최소 분량으로 제한합니다
