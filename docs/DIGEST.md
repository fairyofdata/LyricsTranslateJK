# 다이제스트

2026-11-22 기준 (3축 재설계 반영). 네 문서(README·PLAN·SPEC·DECISIONS, 1,733줄)의 압축본이다. **정본이 아니다** — 어긋나면 각 문서를 따른다.

검토용으로 세 가지를 모아 놓았다: 흩어져 있는 **상수·숫자 전부**(9절), **아직 검증되지 않은 가정**(10절), **이전 판에서 뒤집은 것**(11절).

---

## 1. 한 문단

한국어 가사를 일본어로, 일본어 가사를 한국어로 옮기는 도구. 목표는 **원곡과 같은 소리로 들리면서 작품으로서 말이 되는** 가사다. 번역기가 아니고 벤치마크도 아니다 — CLI와 라이브러리가 산출물이다.

## 2. 철학 — 모든 결정이 여기서 나온다

| | 원칙 | 구현 |
|---|---|---|
| 1 | **소리가 먼저 귀에 닿는다** | `phon`이 1차 축. 모음 지배 |
| 2 | **의미는 작품에 봉사하고 라인에 봉사하지 않는다** | `semantic_work`가 지표, `semantic_line`은 진단 |
| 3 | **공짜가 있으면 받는다** | 소리와 뜻이 겹치면 탐색하지 않고 조회한다 — `sino` |
| 4 | **대체 불가능한 것은 건드리지 않는다** | `keep` |
| 5 | **억지로 끼워 맞추지 않는다** | `mimic`에 품질 하한 `θ_mimic` |

2번과 5번이 이전 판과 가르는 두 줄이다. 이전 판은 라인 충실도를 하한선으로 박아 2번을 어겼고, `mimic`을 비용으로만 다뤄 5번을 어겼다.

**모방하는 것은 사례의 출력이 아니라 이 방향성이다.**

## 3. 축

```
제약    하드 제약        음절·모라 수가 슬롯 구간에 들어맞는가   ← 못 맞추면 후보가 아니다
축 1    phon             원곡 소리와 얼마나 가까운가
축 2    semantic_work    작품의 세계·주제와 정합한가
손잡이  번안율            몇 %를 실제로 목표 언어로 옮기는가
진단    semantic_line    그 라인에 얼마나 충실한가
```

**가중합이 없고 의미 하한선 τ도 없다.** 전선과 손잡이가 그 일을 한다. 그리고 **번안율은 선택이 아니라 필수 부품**이다 — `keep`은 `phon` 거리 0에 의미 보존 완전이므로, 묶지 않으면 아무것도 번역하지 않는 것이 최적해가 된다.

## 4. 왜 일↔한인가 — 공유 자원이 셋이다

| | 공유하는 것 | 예 |
|---|---|---|
| 음소 | [ɯ]·[ɕ]·[tɕ]·[ɾ]·[ŋ] | 일 `ウ` = 한 `ㅡ` — 영·중 상대로는 대응물이 없다 |
| 음절 구조 | 받침 ↔ 특수모라 (ン·ッ·ー) | `밤` ↔ `パム`/`バン` |
| **어휘** | **漢字語 · 서구 차용어** | 残酷 ざんこく / 잔혹 |

세 번째가 중심 자원이고 이전 판에서 빠져 있었다. **1 漢字 = 한국어 1음절**이 예외 없이 성립하므로 漢字語 구간에서는 음절 수의 불확실성이 사라진다. 그리고 中古音 **入聲** 운미가 한국어 받침으로 남고 일본어에서는 모라가 되었다 — 이 세 행(`-k`→ㄱ/`く`, `-t`→ㄹ/`つ`, `-p`→ㅂ/`う`)이 소리 유사도와 길이 차이를 **같은 표에서** 설명한다.

## 5. 네 가지 방출 행위

라인을 어절로 쪼개고 각 구간에 하나를 배정한다. **배정의 조합이 탐색 변수이고 그것이 스펙트럼이다.**

| 행위 | 하는 일 | 출처 | `phon` | 번안율 |
|---|---|---|---|---|
| `keep` | 원어 그대로 둔다 | — | 거리 0 | **빠진다** |
| `sino` | 같은 漢字를 목표 언어 음으로 읽는다 | 표 조회 | 작은 거리 | 들어간다 |
| `mimic` | 음열 격자로 소리를 근사한다 | 탐색 | 격자 비용 | 들어간다 |
| `render` | 뜻 중심으로 생성해 슬롯에 맞춘다 | LLM 표본 | 큰 거리 | 들어간다 |

**배분의 사전 분포는 운율이 아니라 형태론이다.**

```
漢字語 · 차용어    → sino 또는 keep     소리와 뜻을 둘 다 가진다
和語 내용어        → mimic 또는 render  상충한다 — 탐색의 자리
문법형태소         → render             각 언어 문법이 강제한다
```

`keep`이 `sino`를 이기는 조건은 **상징성**이다. 규칙으로 못 정하므로 사용자가 지정하거나 `semantic_work` 기여도로 추정한다.

## 6. 파이프라인

```
원문 라인 + 작품 맥락 + 번안율 구간
  ├─① 음운 분석 → IPA            표준발음 7단계 / 모라 분해       SPEC 4.2
  ├─② 슬롯 템플릿 추출            음절·모라 수 구간               SPEC 1.3
  ├─③ 형태 유형 분류 → 배분 후보   漢字語 / 和語 / 문법형태소       SPEC 8.4
  ├─④ 행위별 생성                 keep·sino 조회 / mimic 격자 / render LLM
  ├─⑤ 격자 → 단어열 해석          사전 lattice + 다목적 빔  ★★★   SPEC 8.3
  ├─⑥ LLM 교정 → 제약 재검사       깨면 버린다 (닫힌 루프)         SPEC 8.6
  └─⑦ 파레토 전선 + 앵커 + 무릎                                   SPEC 8.7
```

⑤가 알맹이다 — 음열은 가사가 아니고, 그 소리가 **실제 단어의 연쇄로 끊어 읽혀야** 한다. 음열 비용과 LM 비용을 **하나의 빔**으로 함께 탐색한다.

**빔은 다목적이다.** 이전 판의 실제 결함이 여기였다 — 음열 비용으로만 가지치면 의미가 뛰어나고 소리가 중간인 후보가 **애초에 생성되지 않고**, 전선이 소리 쪽 끝만 채워진 채 "스펙트럼"으로 불린다.

## 7. 좌표계 — 레퍼런스가 없어도 선다

`phon = 0.7`은 아무 뜻이 없다. 상대 위치만 뜻이 있다. 기준점을 **모든 라인에서 계산되는 세 앵커**로 둔다.

| 앵커 | 뜻 |
|---|---|
| 음차 상한 | 의미 무시 음열 최적 — "이 라인에서 가능한 최대 소리 유사도" |
| MT 상한 | 발음 제약 없는 번역 — "소리를 포기하면 얻는 의미" |
| 원어 유지 | 전 구간 `keep` — 번안율 0의 자명한 점 |

후보는 "가능한 최대의 82%, MT 의미의 71%, 번안율 85%"로 읽힌다. **상한은 관찰된 한 점보다 낫다** — 언제나 존재하고 해석이 분명하다.

기본 제시점은 **전선의 무릎**(최대 곡률). 손 상수 없이 전선의 형태에서만 나온다.

## 8. 레퍼런스와 모범 사례 — 역할이 다르다

| | n=1에서 | 쓰임 |
|---|---|---|
| **모범 사례** (골드 표준) | **충분하다** — 참조 구현과 수용 기준은 원래 하나다 | 네 가지 **역량 시험**, M1부터 회귀 |
| **통계 표본** | **쓸 수 없다** | 팬 커버 코퍼스, RQ2·RQ4·RQ5 |

### 수용 기준 — 출력 일치가 아니라 역량

| | 기준 | 실패가 알려주는 것 |
|---|---|---|
| 1 | 칭찬받은 대응이 후보 집합에 **존재하는가** (1위일 것을 요구하지 않는다) | 거리 함수가 그 수를 못 본다 |
| 2 | 형태 유형 배분이 실제 배분과 겹치는가. 상징적 후렴에 `keep`을 올리는가 | 사전 분포가 틀렸다 |
| 3 | `semantic_work` 높음 + **`semantic_line` 낮음**을 맞게 내는가 | 점수 함수의 **부호가** 틀렸다 |
| 4 | 그 번안율을 지정했을 때 전선이 그 영역을 지나는가 | 전선이 그 영역을 못 본다 |

### 레퍼런스는 팬 커버다

| | 공식 번안 | 팬 커버 |
|---|---|---|
| 과제 일치 | **아니다** — 발음 우선을 시도하지 않았다 | **그렇다** |
| 선율 동일성 | 바뀐 경우가 있다 | **원곡 음원에 부른다 — 정의상 동일** |
| 라인 대응 | 합치고 쪼갠다 | **거의 1:1** |
| 같은 곡 복수 번안 | 거의 없다 | **흔하다** — 스펙트럼의 여러 점 |
| 평가 데이터 | 없다 | **댓글** |

**댓글에서 쓰는 것은 좋아요 수가 아니라 특정 대응을 지목한 댓글**이다. 사람이 손으로 달아 준 "이 대응은 작동한다" 라벨이고, `phon` 모수와 `θ_mimic`을 맞출 신호가 된다. 공식 번안에는 존재하지 않았다.

## 9. 모든 숫자 — 한 곳에

**비용값** (SPEC 2절)

| 한→일 | 비용 | | 일→한 | 비용 |
|---|---|---|---|---|
| ㄴ·ㅇ → ン | 0 | | ン → 받침 ㄴ/ㅇ | 0 |
| ㅁ → ン | 0.1 | | ッ → 받침 ㄱㅂㄷ | 0.1 |

**임계·상수**

| 기호 | 값 | 출처 |
|---|---|---|
| `slot_min`/`slot_max` | 받침 음절 1~2, 그 외 1~1. **漢字語 구간은 1~1** | 규칙 |
| `C(라인)` | 무관한 실제 라인 `M`개와의 평균 거리 (슬롯 수 일치) | **데이터** |
| **`θ_mimic`** | **품질 하한** — 댓글 라벨에서 작동 판정된 대응의 거리 상단 | **데이터** (예산 아님) |
| **`w_v`·`w_c`·`w_f`** | 핵모음 : 자음 : 위치 가중. `w_v > w_c` | **데이터** (댓글 라벨) |
| 번안율 구간 | `[r_min, r_max]` — 사용자 지정, 기본값 명시·고정 | 사용자 |
| `λ_mel`·`λ_hold`·`λ_rest` | 고정 + ±50% 민감도 (DP 채점 경로만) | 손 |
| `θ`·`B` | 포화점까지 키워 고정 | 계산 예산 |
| `K` | 200 (사전 해석 출력 수) | 계산 예산 |
| `N` | 8 (제시용, **비교에 쓰지 않는다**) | UI |
| `ε` | 음소 하나의 평균 자질 거리 | 규칙 |
| `k` | 24 (베이스라인 공통 예산), 곡선 1·4·8·16·24 | 실험 설계 |
| `M` | 100 (`C` 추정 표본 수) | 계산 예산 |
| `n_s` | 8 (`render` 표본 수, 배분별 캐시) | 계산 예산 |
| `λ_split`·`λ_drop` | 정렬 DP 유형 벌점 — **어떤 지표에도 안 들어간다** | 손 |
| `V` | 일본어 ≈110 모라 / 한국어 상위 **2,000** 음절 | **미검증** |

**`θ_mimic`과 `w_*`는 계산 예산이 아니다.** 무엇이 허용되고 무엇이 더 좋은지를 바꾸므로 따로 보고한다.

## 10. 아직 검증되지 않은 가정

치명도 순이다. 앞의 둘은 코드가 거의 없이 돌아간다.

| | 가정 | 확인 | 틀리면 |
|---|---|---|---|
| ① | **가사의 漢字語 비율이 충분하다** | **분기점 A (M1 초)** | `sino`·`keep`의 이점이 작아지고 설계의 중심 근거가 약해진다. `mimic`이 하중을 전부 받는다. 단일 언어 가사와 漢字 사전만으로 측정된다 |
| ② | **좁은 슬롯 구간으로 팬 커버 포함률이 높다** | **분기점 B (M1 종료)** | 템플릿 경로 실패. 음원 전사를 기본 경로로 되돌려야 하고 도구의 쓸모가 크게 줄어든다 |
| ③ | LaBSE가 일↔한에서 쓸 만하다 | M1 초 | 라인 정렬과 `semantic_work`가 함께 흔들린다. 섹션 라인 수가 같은 구간의 검색 정확도로 재고, 정렬 결과가 필요 없다 |
| ④ | 격자가 사람이 찾아낸 음열을 담는다 | 분기점 C (M2) | 거리 함수나 재음절화 규칙이 틀렸다. 모범 사례 쪽이 먼저 돌고 진단이 구체적이다 |
| ⑤ | 라인당 유효 후보가 ≥1개 | 분기점 D (M3) | 배분을 `sino`·`render`로 옮긴다. **`keep`이 바닥이므로 결과가 없는 상황은 구조적으로 발생하지 않는다** |
| ⑥ | **형태론이 배분을 예측한다** | RQ2 (M6) | 이 프로젝트의 고유 기여이자 가장 검증이 필요한 주장. 깨지면 사전 분포를 다시 세운다 |
| ⑦ | `semantic_work`가 작품 정합성을 잡는다 | M5~M6 | LLM 심판을 보조 축으로 둔다. 둘의 상관을 보고한다 |
| ⑧ | 자질 거리가 사람 귀와 맞는다 | RQ5 (M7) | 1차 목적 함수가 틀렸다. 모수 서넛을 라벨로 맞추고 과정을 보고한다 |
| ⑨ | 팬 커버 코퍼스가 모인다 | M0 | 공식 번안보다 문턱이 낮다는 판단이고 **실사 결과가 아니다** |
| ⑩ | 한국어 상위 2,000 음절 커버리지 | M2 | `V`를 키워야 하고 응답 시간이 흔들린다 |

## 11. 이전 판에서 뒤집은 것

| | 뒤집은 것 | 왜 |
|---|---|---|
| X9 | 의미 하한선 τ | **재는 양이 틀렸다** — 라인 충실도가 아니라 작품 정합성이다. 가장 좋은 후보를 거르는 필터였다. 게다가 τ를 공식 번안 분포에서 뽑았으므로 그 90% 통과는 **정의상**이었다 |
| X10 | τ·필터는 라인 단위 코사인 | 필터 자체가 없어지면서 문제가 사라졌다. `semantic_work`가 축, `semantic_line`이 진단 |
| X11 | 공식 번안 쌍 20~30곡 | **구성 불일치.** 그 번안가들은 우리 과제를 하지 않았다. 수집 난이도는 부차적이었다 — 처음부터 다른 모수를 재고 있었다 |

함께 바뀐 것: 사전식 우선순위 → 전선 + 손잡이(D7), 공식 번안 좌표 → 계산된 앵커(D8), 부분 음차 → 네 행위 배분(D22·D32), 음표 길이·강박 배분 → 형태론 배분(D33), 사람 평가 중심 → 댓글 라벨 + 평정(D10).
