# 다이제스트

2026-11-15 기준 (공백 보강 반영). 네 문서(README·PLAN·SPEC·DECISIONS, 1,330줄)의 압축본이다. **정본이 아니다** — 어긋나면 각 문서를 따른다.

검토용으로 만들었으므로 세 가지를 모아 놓았다: 흩어져 있는 **상수·숫자 전부**(10절), **아직 검증되지 않은 가정**(11절), **아직 비어 있는 설계**(12절).

---

## 1. 한 문단

한국어 가사를 일본어로, 일본어 가사를 한국어로 **번안**하는 도구. 원곡과 소리가 비슷하게 들리면서 뜻도 통해야 하고, 같은 선율에 얹히므로 음절·모라 수가 하드 제약으로 걸린다. 번역기가 아니고, 벤치마크도 아니다 — CLI와 라이브러리가 산출물이다.

## 2. 우선순위 (모든 설계가 여기서 따라 나온다)

```
0. 하드 제약   음절·모라 수가 선율 슬롯 구간에 들어맞는가   ← 못 맞추면 후보가 아니다
1. 발음 유사도  원곡 소리와 얼마나 가까운가                 ← 탐색의 목적 함수
2. 의미 + 화용  뜻이 통하고 그 언어 가사로서 말이 되는가     ← 하한선 필터 τ
3. 나머지      운율·악센트·어투                            ← 진단만
```

**사전식이다.** 순서가 주어졌으므로 가중합이 없고, 맞출 가중치가 없다. 이전 판의 6성분 가중합과 손 상수 스물 몇 개가 여기서 사라졌다 (D7, X2).

## 3. 왜 일↔한인가

[ɯ]·[ɕ]·[tɕ]·[ɾ]·[ŋ] 을 공유한다. 특히 비원순 고모음 [ɯ](일 ウ / 한 ㅡ)는 영어·중국어 상대로는 대응물이 없다. 음절 구조도 가깝다 — 한국어 받침과 일본어 특수모라(ン·ッ·ー)가 서로 대응 경로를 갖는다.

**"소리를 흉내내면서 뜻도 살린다"가 실제로 가능한 드문 쌍이다.** 영↔한으로는 잘 돌지 않을 것이고, 그건 한계가 아니라 이 쌍을 고른 이유다.

## 4. 왜 LLM으로는 안 되는가

**자기가 낸 결과의 소리를 재지 못하기 때문이다.** 토큰을 뱉을 때 음소열을 계산하지 않으므로 발음 유사도를 목표로 삼을 수가 없다. 결과는 "그럴듯한 번역 + 운 좋으면 몇 음절 비슷함"이다.

그래서 순서를 뒤집는다 — 번역한 뒤 발음을 보지 않고, **발음을 깔고 그 위에서 말이 되는 것을 찾는다.** LLM은 마지막 교정기다 (D21).

## 5. 파이프라인

```
원문 라인
  ├─① 음운 분석 → IPA           표준발음 7단계 / 모라 분해       SPEC 4.2
  ├─② 슬롯 템플릿 추출           음절·모라 수 구간, 장음, 호흡    SPEC 1.3
  ├─③ 음열 격자 생성             받침↔특수모라 표가 전이 비용표   SPEC 8.2
  ├─④ 격자 → 단어열 해석         사전 lattice + LM 통합 빔  ★★★  SPEC 8.3
  ├─⑤ 의미 하한선 필터           LaBSE 코사인 ≥ τ                SPEC 8.5
  ├─⑥ LLM 교정 → 제약 재검사      깨면 버린다 (닫힌 루프)         SPEC 8.6
  └─⑦ 파레토 전선 → 후보 N개 + (발음 점수, 의미 점수)             SPEC 8.7
```

**도구의 단위는 사용자가 준 라인이고, 코퍼스의 단위는 분절이다** — 공식 번안은 라인 경계를 보존하지 않는다 (D25, SPEC 11).

③~⑥이 본체. ①②는 기반 공사, ⑦은 제시 계층. **④가 알맹이다** — 음열은 가사가 아니고, 그 소리가 실제 단어의 연쇄로 끊어 읽혀야 한다. ③과 ④는 분리하지 않고 **하나의 빔**으로 함께 탐색한다(음열 비용만으로 빔을 채우면 음운적으로 완벽하지만 단어가 아닌 경로로 빔이 꽉 찬다).

## 6. 설계를 지탱하는 다섯 개

| | 장치 | 하는 일 |
|---|---|---|
| D2 | **슬롯 IR** `note`/`extend`/`rest` | 일본어 특수모라와 한국어 받침이 `extend`에서 만난다. "일 N모라 ≈ 한 N−(특수모라 수) 음절"이 통계가 아니라 규칙에서 따라온다 |
| D3 | **받침↔특수모라 표 = 전이 비용표** | 대응표가 문서가 아니라 실행 코드다. 동시에 검증 대상(공식 번안에서 실제 대응 빈도를 재어 맞는지 본다) |
| D14 | **하드 제약은 구조로 금지** | 음절 수 불일치를 큰 비용으로 벌하지 않는다. 격자 노드가 슬롯 인덱스를 들고 있어 구간 밖 경로는 종료 노드에 닿지 못한다. "조금 나쁨"과 "불가능"을 한 스칼라에 섞지 않는다 |
| D22 | **부분 음차 1급** | 운율적으로 두드러진 어절만 음차하고 나머지는 의미 중심. 폴백이 아니라 설계의 일부 — `\|S\|=1`까지 줄이면 거의 항상 해가 있고, 이것이 "결과가 아예 없음"을 막는 바닥이다 |
| D24 | **슬롯 수는 점이 아니라 구간** | 받침이 같은 음표에서 실현되는지(`밤`) 뒤 음표로 넘어가는지(`바-ㅁ`)는 선율이 정하고 텍스트로는 모른다. `slot_min`/`slot_max`로 드러내고 **충족률과 평균 구간 폭을 언제나 함께 보고한다** |

## 7. 손 상수를 없앤 두 자리, 그리고 남은 자리

| | 어떻게 |
|---|---|
| **가중합** | 없앴다. 우선순위가 사전식이므로 (D7) |
| **의미 하한선 τ** | 데이터에서 나온다 — 개발 집합 공식 번안의 **라인 단위** 의미 코사인 **하위 10분위**, 방향별. 그중 **구조적으로 강제된 `1:1` 분절만** 쓴다(D25·D28). "숙련된 번안가가 실제로 허용한 만큼 허용한다" (D20) |
| **탐색 하이퍼파라미터** | **남아 있다** — θ·B·K·N·ε·M·n_s. 숨기지 않는다 (SPEC 8.9). X2에서 버린 가중치와는 성질이 다르다: 무엇이 더 좋은지를 바꾸지 않고 **얼마나 넓게 보는지만** 바꾼다. 목적 함수와 하한선에는 들어가지 않으므로 계산 예산으로 취급하고 포화점을 보고한다 |

## 8. 음원이 필요 없다 (기본 경로)

하드 제약은 음절 수이고, 그건 텍스트에서 정확히 나온다. 선율 전사(보컬 분리 → F0 → 음표 분할 → 음절 정렬)와 합성-ASR 평가는 **선택 층**이다 — 음표 길이에 의존하는 판정(6.2)이나 "실제로 불러서 알아들을 수 있는가"(6.4)를 재려는 경우에만 쓴다.

**이유:** 도구가 음원을 요구하면 쓸 수 없다. 사용자는 가사를 들고 오지 음원과 전사 파이프라인을 들고 오지 않는다 (D4).

## 9. 평가의 뼈대

공식 번안을 **같은 파이프라인**에 넣어 두 점수를 재고 평면에 찍는다. 절대 점수로는 아무 말도 못 하지만 상대 위치는 뜻이 있다 — "공식판보다 소리는 가깝고 뜻은 조금 멀다". **이것이 평가이면서 동시에 도구의 UI다** (D8, D19).

주장은 "더 좋다"가 아니라 **파레토 전선을 바깥으로 민다**이고 2D 초부피로 측정한다. 베이스라인은 LLM 직접 / LLM+재순위 / 공식 번안 / 의미 중심 MT. **후보 예산을 맞춘다** — 초부피는 후보 수에 단조 증가하므로 라인당 동일 예산 `k`를 주고 예산 곡선으로 보고한다.

| | 연구 질문 | 음원 |
|---|---|---|
| RQ1 | 격자+사전 탐색이 LLM 직접 프롬프트보다 전선을 바깥으로 미는가 | 불필요 |
| RQ2 | 부분 음차가 전체 음차보다 나은가, 음차 위치를 어디에 둘 때 이득인가 | 불필요 |
| RQ3 | 두 방향은 얼마나 비대칭인가 (받침 전개 ↔ 특수모라 흡수) | 불필요 |
| RQ4 | 공식 번안은 이 평면의 어디에 있는가 — 번안가는 실제로 소리를 얼마나 쓰는가 | 음차율·라인 내 위치는 불필요 / **음표 길이와의 관계만 전사 부분집합** |
| RQ5 | 자질 거리 발음 점수가 사람 귀와 맞는가 (Spearman ρ) | 불필요 |

## 11. 아직 검증되지 않은 가정

도구가 서는지 마는지가 여기 걸려 있다. 위에서 아래로 치명적인 순이다.

| | 가정 | 확인 시점 | 틀리면 |
|---|---|---|---|
| ① | **좁은 슬롯 구간으로 공식 번안 포함률이 높게 나온다** | **분기점 0 (M1 종료)** | 템플릿 경로가 실패. 음원 전사를 기본 경로로 되돌려야 하고 도구의 쓸모가 크게 줄어든다. 설계를 다시 본다 |
| ② | 격자→단어열에서 라인당 유효 후보가 ≥1개 나온다 | 분기점 2 (M3 종료) | **리스크 최고.** 부분 음차(M5)를 앞으로 당긴다. `\|S\|=1`이 바닥이다 |
| ③ | **LaBSE가 일↔한에서 쓸 만하다** | **M1 초 — 가장 먼저 된다** | 세 곳에서 하중을 받는다: 라인 정렬·τ·의미 점수. 섹션 라인 수가 같은 구간에서 진짜 대응이 코사인 1위로 뽑히는 비율만 재면 되고 정렬 결과가 필요 없다. 낮으면 정렬이 수동으로 가고 의미 축 전체의 신뢰도가 함께 흔들린다 |
| ④ | 생성한 격자가 공식 번안의 실제 음열을 담는다 | 분기점 1 (M2 종료) | 거리 함수나 재음절화 규칙이 틀렸다. 공식 번안은 사람이 찾아낸 해이므로 격자 안에 있어야 한다 |
| ⑤ | 공식 번안 쌍 20~30곡이 실제로 모인다 | M0 | PLAN 리스크표의 "낮음"은 *가사 텍스트만 필요하다*는 근거일 뿐 **실사 결과가 아니다.** 미달이면 공유 선율 동요·찬송가로 보강 |
| ⑥ | 의미 기반 라인 정렬이 수렴한다 (`dp_agreement`) | M1 | 수동 정렬 비중이 커지고 M1이 더 늘어난다. 수렴하지 않는 곡은 버리므로 코퍼스가 줄어든다 |
| ⑦ | 한국어 상위 2,000 음절이 실제 가사 토큰의 대부분을 덮는다 | M2 | `V`를 키워야 하고 응답 시간 목표가 흔들린다 |
| ⑧ | 조음 자질 거리가 사람 귀와 맞는다 | RQ5 (M7) | 1순위 목적 함수가 틀린 것이다. 자질 가중을 고치고 그 과정을 보고한다 |

**①이 가장 결정적이고, ③이 가장 값싸다.** ③은 섹션 라벨과 임베딩만으로 되므로 코드가 거의 없이 M1 첫날에 돌아가고, 결과가 나쁘면 ①의 측정 방법 자체를 다시 설계해야 한다(정렬이 의미에 의존하기 때문이다). **그래서 순서는 ③ → ① 이다.**

## 12. 메운 공백 — 무엇을 어떻게 정했나

11월 15일 검토에서 나온 여섯 개를 전부 메웠다. 셋은 실제 설계 결정이었고(D25·D26·D27), 하나는 선택이었고(D28), 둘은 선언과 정렬이었다.

**① 라인 대응 — 가장 컸다. → D25**

코퍼스의 단위를 라인에서 **분절**로 바꿨다. 공식 번안은 라인 경계를 보존하지 않지만 **선율은 안 바뀐다** — 번안가가 두 라인을 합쳤어도 합친 구간의 음절 총량은 같은 제약을 받는다. 라인 경계는 가사지의 표기일 뿐이다.

대응은 **의미 유사도 + 섹션 구조**로 DP 제안을 내고 사람이 검수한다. 여기서 순환 두 개가 나왔고 반대 방향으로 끌어당긴다.

| 순환 | 어떻게 피했나 |
|---|---|
| 1.2의 **길이비 규칙으로 정렬**하면, 그 정렬로 길이비를 검증하는 분기점 0이 자동 통과한다 | 정렬 비용에 **길이 항을 넣지 않는다.** 의미와 구조만 쓴다 |
| 그러면 **의미로 고른 대응**의 코사인 분포가 위로 치우쳐 거기서 뽑은 τ가 과도하게 엄격해진다 | τ는 **구조적으로 강제된 `1:1` 분절만** 쓴다 (섹션 라인 수가 양 언어에서 같고 사람이 확인 — DP가 고른 것이 없다). 강제 집합과 전체 집합에서 각각 추정해 차이를 공개한다 |

**② 비음차 구간의 생성기 → D26**

LLM이 생성한다. **D21을 깨지 않는다** — D21이 금지한 것은 LLM이 *발음을 목표로 삼는* 것이고 근거는 자기 출력의 음소열을 재지 못한다는 것이다. 비음차 구간에서는 1순위가 비어 **의미가 1순위로 올라오므로** 그 금지에 걸리지 않고, 하드 제약은 구조적 필터가 쥔다.

대가는 모델 의존성이다. 그래서 RQ1의 주장을 **"LLM을 쓰지 않는다"에서 "격자가 음차 구간을 쥐면 전선이 바깥으로 밀린다"로 바꿨다.** 호출 수는 `(라인, 음차 위치 집합 S)`로 캐시해 `K·n_s`(1,600회)에서 `S` 종류 수 × `n_s`로 줄인다 — 비음차 텍스트는 격자 경로가 아니라 `S`에만 의존한다.

**③ 정규화 상수 → D27**

`C`를 **라인별**로 두고, 목표 언어의 **무관한 실제 라인** `M=100`개(다른 곡, 슬롯 수 구간 일치)와의 평균 거리로 추정한다. 균등 무작위 모라열은 실제 가사보다 멀어서(실제 텍스트는 빈도 구조가 있다) `C`가 과대평가되고 모든 점수가 높게 뜬다. 길이를 맞추지 않으면 `C`가 "무관한 소리"가 아니라 "길이가 틀림"을 잰다.

**④ τ의 단위 → D28**

**라인 단위**를 쓴다. 윈도우 값이 더 관대하지만 라인마다 독립 적용하면 **한 원문 라인의 의미를 모든 라인이 돌려 쓰면서 전부 통과하는 구멍**이 생긴다. ±1 윈도우는 진단·곡 단위 비교로 내렸다.

**⑤ τ 통과의 순환 → 선언**

τ를 공식 번안 분포의 하위 10분위로 정의했으므로 약 90%는 **정의상** 통과한다. 통과율을 품질 근거로 보고하지 않는다. 쓸 수 있는 것은 하나 — 테스트 집합 공식 번안이 개발 집합 τ 아래로 떨어지는 비율이 10%에서 크게 벗어나는지. **결과가 아니라 점검이다.**

**⑥ 베이스라인 모델 → D29**

베이스라인·교정기·비음차 생성기가 **같은 모델·같은 리비전**을 쓴다. 약하면 허수아비를 이기고 강하면 모델 강도에 오염된다. 맞추면 **"우리 파이프라인 − 격자"가 정확히 베이스라인**이 되어 절제가 깔끔해진다. 한 조건은 다른 모델로 재확인한다.

### 대신 새로 생긴 것

- **LaBSE가 세 곳에서 하중을 받는다** — 라인 정렬, τ, 의미 점수. 임베딩이 이 쌍에서 약하면 셋이 동시에 흔들린다. 11절 ③으로 올렸고, 정렬 결과 없이 재는 방법을 SPEC 11.2에 적었다
- **M1이 3주에서 4주로** 늘었다. 라인 대응은 이전 판에 아예 없던 작업이다
- **손 상수 둘**(`λ_split`·`λ_drop`)이 늘었지만 어떤 지표에도 들어가지 않는다 — 제안의 순서만 바꾸고 최종 권한은 사람 검수에 있다
- 부분 음차 경로의 **체감 시간은 LLM 호출이 지배한다.** 2초 목표는 탐색부의 것이므로 호출 시간을 따로 보고한다
