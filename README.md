# LyricsTranslateJK

**발음 우선 일본어↔한국어 가사 번안 도구.**

원곡과 소리가 비슷하게 들리면서 뜻도 통하는 번안을 찾는다. 번역이 아니라 번안이고, 같은 선율에 얹혀야 하므로 음절·모라 수가 하드 제약으로 걸린다.

```
우선순위   0. 음절 수가 맞는가      ← 못 맞추면 후보가 아니다
          1. 원곡과 소리가 가까운가
          2. 뜻이 통하고 말이 되는가
          3. 운율·악센트·어투
```

## 왜 일↔한인가

발음 우선 번안은 두 언어가 음소를 공유해야 성립한다. 일본어와 한국어는 **[ɯ]·[ɕ]·[tɕ]·[ɾ]·[ŋ]** 을 공유한다. 특히 비원순 고모음 [ɯ](일본어 ウ, 한국어 ㅡ)는 영어·중국어 상대로는 대응물이 없다.

음절 구조도 가깝다. 한국어 받침과 일본어 특수모라(ン·ッ·ー)가 서로 대응 경로를 가지므로, `밤`은 `パム`나 `バン`이 되고 `サン`은 `산`이 된다. 이 대응표가 탐색의 전이 비용표가 된다.

## LLM에게 시키면 안 되는 이유

"발음 비슷하게 번안해줘"는 LLM이 못 한다. **자기가 낸 결과의 소리를 재지 못하기 때문이다.** 토큰을 뱉을 때 음소열을 계산하지 않으므로 발음 유사도를 목표로 삼을 수가 없다.

그래서 순서를 뒤집는다 — 번역한 뒤 발음을 보지 않고, **발음을 깔고 그 위에서 말이 되는 것을 찾는다.**

```
원문 라인
  │
  ├─① 음운 분석 → IPA            표준발음 규칙 / 모라 분해
  ├─② 슬롯 템플릿 추출            음절·모라 수, 장음 위치
  │
  ├─③ 목표 언어 음열 격자 생성     IPA 거리 비용을 단 전이 격자
  ├─④ 격자 → 단어열 해석          사전 lattice + LM 빔 서치   ★ 핵심 난관
  ├─⑤ 의미 하한선 필터            공식 번안 분포에서 유도한 τ
  ├─⑥ LLM 교정 → 제약 재검사       깨면 버린다 (닫힌 루프)
  │
  └─⑦ 후보 N개 + (발음 점수, 의미 점수)
```

④가 알맹이다. 음열은 가사가 아니다 — 그 소리가 **실제 단어의 연쇄로 끊어 읽혀야** 한다.

## 출력은 정답 하나가 아니다

발음과 의미는 실제로 상충한다. 어디서 타협할지는 곡과 용도에 따라 다르고 도구가 알 수 없으므로, 후보 N개를 두 점수와 함께 내놓고 **공식 번안의 좌표를 같이 찍는다.** 사용자는 "공식판보다 소리는 가깝고 뜻은 조금 멀다" 같은 위치로 읽고 고른다.

즉 파레토 전선이 연구 결과가 아니라 인터페이스다.

## 음원이 필요 없다

기본 경로는 원문 가사에서 유도한 음절·모라 수 템플릿으로 동작한다. 발음 우선 번안의 하드 제약은 음절 수이고, 그건 텍스트에서 정확히 나온다.

음원 전사(보컬 분리 → F0 → 음표 분할 → 음절 정렬)와 합성-ASR 평가는 **선택 층**이다. 음표 길이에 의존하는 판정이나 "실제로 불러서 알아들을 수 있는가"를 재려는 경우에만 쓴다.

## 데이터

학습 데이터가 필요 없다. 쌍으로 학습하지 않고 음운 규칙·사전·거리 함수로 탐색하며, 사전 훈련된 공개 모델만 쓴다.

공식 번안 쌍 20~30곡은 **평가용**이다 — 기준 좌표, 의미 하한선 τ의 추정, 번안가가 실제로 소리를 얼마나 쓰는지의 분석. 가사·음원·선율은 재배포하지 않고, 공개하는 것은 코드·규칙표·거리 함수·추상 특징·해시·평가 스크립트다.
