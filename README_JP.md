# LyricsTranslateJK

[English](README.md) · [한국어](README_KR.md) · [日本語](README_JP.md)

**音を守る日本語↔韓国語の歌詞翻案ツール。**

原曲と同じ音に聞こえ、なおかつ作品として意味が通る歌詞を探します。翻訳ではなく翻案で、同じ旋律に乗らなければならないため、音節・モーラ数がハード制約になります。

```
制約      ハード制約        音節・モーラ数がスロット区間に合うか   ← 合わなければ候補ではない
軸 1      phon             原曲の音にどれだけ近いか
軸 2      semantic_work    作品の世界・主題と整合するか
つまみ    翻案率            何 % を実際に目標言語へ移すか
診断      semantic_line    その行にどれだけ忠実か
```

加重和も意味の下限もありません。**パレート前線とつまみがその役を担います。**

## 哲学

| | 原則 |
|---|---|
| 1 | 音が先に耳に届く |
| 2 | **意味は作品に奉仕し、行には奉仕しない** |
| 3 | ただで手に入るものは受け取る — 音と意味が重なるなら探索せず引く |
| 4 | 代わりのきかないものには触れない |
| 5 | **無理にはめ込まない** — 悪い音写は音写しないより悪い |

## なぜ日↔韓か

共有資源が三つあります。**音素** [ɯ]·[ɕ]·[tɕ]·[ɾ]·[ŋ] — 特に非円唇の高母音 [ɯ]（日 `ウ`、韓 `ㅡ`）は英語・中国語相手には対応物がありません。**音節構造** — パッチムと特殊モーラ（ン·ッ·ー）が互いに対応経路を持ちます。そして**語彙** — 漢字語と西洋からの借用語で、二つの言語は同じ文字をそれぞれの音で読みます。

三つ目が核心です。`残酷` は ざんこく であり 잔혹 です — **音と意味を同時に持ちます。** そこには相克がなく、探索ではなく辞書を引けば済みます。

## 四つの出力行為

行を語節に分け、各区間に一つを割り当てます。**割り当ての組み合わせがスペクトラムです。**

| | すること |
|---|---|
| `keep` | 原語のまま置く — 象徴性が代えられない箇所 |
| `sino` | 同じ漢字を目標言語の音で読む |
| `mimic` | 音列ラティスで音を近似する |
| `render` | 意味中心に生成してスロットに合わせる |

割り当ての事前分布は韻律ではなく**形態論**です — 漢字語は `sino`·`keep`、和語の内容語は `mimic`·`render`、文法形態素は `render`（各言語の文法が強制する）。

## LLM に任せてはいけない理由

「発音が似るように翻案して」は LLM にはできません。**自分の出力の音素列を測れないからです。** トークンを出すときに IPA を計算していないので、発音の類似度を目標にできません。

そこで順序を逆にします — 翻訳してから発音を見るのではなく、**音を先に敷き、その上で意味が通るものを探します。** LLM は `render` の生成器と校正器としてだけ使います。

```
原文の行 + 作品の文脈 + 翻案率の区間
  ├─① 音韻分析 → IPA
  ├─② スロットテンプレート抽出        音節・モーラ数の区間
  ├─③ 形態タイプ分類 → 割り当て候補
  ├─④ 行為ごとの生成                 辞書引き / ラティス / LLM 標本
  ├─⑤ ラティス → 単語列の解釈         辞書ラティス + 多目的ビーム   ★ 核心の難所
  ├─⑥ LLM 校正 → 制約の再検査         破れば捨てる（閉ループ）
  └─⑦ パレート前線 + アンカー + ニー
```

## 出力は正解一つではない

二つの軸は実際に相克します。どこで妥協するかは曲と用途によって違い、ツールには分からないので、候補 N 個を三つの値とともに出します。

座標系を立てるのは参照ではなく**計算されたアンカー**です — 音写の上限（可能な最大の音の類似度）、MT の上限（音を諦めれば得られる意味）、原語維持（翻案率 0）。すべての行で計算されるので、参照のない実際の使用場面でも成り立ちます。既定の提示点は**前線のニー**で、手で決めた定数はありません。

## 音源は要らない

既定の経路は、原文の歌詞から導いた音節・モーラ数のテンプレートで動きます。音源の書き起こしと合成-ASR 評価は**選択層**です。

## データ

学習データは要りません。対から学習せず、音韻規則・辞書・距離関数で探索し、事前学習済みの公開モデルだけを使います。

参照は**ファンカバー**です — 公式の訳詞家は発音優先の翻案を試みたことがなく、構成が合いません。ファンカバーは原曲の音源に乗せて歌うので旋律は定義上同一で、同じ曲に志向の違うカバーが複数あってスペクトラムの複数の点をくれます。そして**特定の対応を名指ししたコメント**が「この対応は効いている」という人のラベルになります。

歌詞・音源・旋律・コメント本文は再配布しません。公開するのはコード・規則表・距離関数・抽象特徴・ハッシュ・評価スクリプトです。
